# SCAU-UFM 数据提交指南（面向数据所有方）

版本 1 · 2026-09-27 · 适用于 D-5 真实城市数据入库（M281 解除阻塞路径）

这份指南写给**提供数据的单位**（水务、规划、测绘、设计院等），不需要了解模型内部。
您只需按第 2 节准备文件、按第 3 节回答问题、按第 4 节签署即可。
技术细节在上级目录的 `README.md` 和本目录两份 checklist 中，供双方技术人员对照。

---

## 1. 先说清楚三件事

1. **只要一小块区域。** 几百米见方、含十几栋建筑和一小段管网即可。目的是验证数据链路，不是做全市模型。
2. **不要替我们加工。** 请提供原始数据（原始坐标系、原始字段名、原始单位）；网格、糙率、孔隙率等模型参数由平台从原始数据推导，您不需要提供。
3. **授权是必需的。** 没有书面授权和格式承诺的数据，无论多完整，项目都不能入库、不能出现在测试证据里。这是项目决策记录（M281）的硬性要求，模拟/合成数据不能替代。

---

## 2. 要交什么

按下表准备。"必须一起说明"一栏的内容写在第 3 节的问答里即可，不必另做文档。

| # | 要交的 | 常见来源 | 可接受格式 | 必须一起说明 |
|---|---|---|---|---|
| ① | **计算范围** | 规划红线、排水分区、研究区边界 | Shapefile 或 GeoJSON；**一个**闭合多边形 | 坐标系（如 CGCS2000 3 度带 EPSG:4547） |
| ② | **地形 DEM** | 测绘院、无人机、LiDAR、市政竣工测量 | GeoTIFF 或 ESRI ASCII Grid（`.asc`） | 坐标系；**高程基准**（1985 国家高程 / 地方高程 / 其他）；分辩率；NoData 值；**是裸地 DEM 还是含建筑的 DSM** |
| ③ | **建筑轮廓** | 房屋普查、基础地理数据库 | Shapefile 或 GeoJSON | 每栋建筑一个**稳定不变的唯一编号**（字段名）；有无高度字段；有无屋面排水去向字段 |
| ④ | **地表类型** | 土地利用现状、用地分类、路面材质 | Shapefile 或 GeoJSON | 类别编码表：每个编码代表什么（道路 / 绿地 / 屋面 / 裸土 / 水面……） |
| ⑤ | **排水管网模型** | 水务部门 SWMM 模型；或 GIS 管网数据 | **SWMM 5.2.x 的 `.inp` 文件**，连同它引用的全部外部文件（雨型、时间序列、曲线等） | 单位制（推荐 CMS / 米）；检查井编号稳定；**一张对照表：地面哪个雨水口 / 哪片屋面接到哪个检查井**（Excel 或 CSV 即可） |
| ⑥ | **一页说明** | 数据所有方填写 | 文本 / Word | 见第 4 节 |

**可选 ⑦ 河道模型**：研究区有河道且希望做河网耦合时，另交 D-Flow FM 案例（`.mdu`、`.ext`、`.bc`、网络文件及全部引用文件）、D-Flow FM 版本号，以及"河道每个边界对应地表哪一段、是进流还是出流"的对照表。**这一项可以以后补交，不影响前六项先入库。**

**可选**：土壤分区及入渗参数（Green-Ampt 参数须注明单位）；如全区土壤均匀或另有来源，可不交。

关于管网数据的补充说明：

- 如果只有 GIS 管网（管线 / 检查井图层）而没有 SWMM 模型，也可以交，但请注明管径、管底标高、井底标高、井盖标高的字段和单位；由项目方在授权范围内作者化为 SWMM 输入，再由您确认。
- `.inp` 中**不要**包含子汇水区产流（`[SUBCATCHMENTS]` 等）：地表产流由二维地表模型承担，平台会拒绝含产流段的管网文件。

## 3. 需要您回答的 12 个问题

请逐条作答（可直接写在第 4 节说明页里）。答"不知道"也可以，但不能空着——空着的项目项目方不会替您猜。

| # | 问题 | 为什么要问 |
|---|---|---|
| 1 | 数据授权给本项目用于哪些用途？可否入库、可否出现在公开测试记录里？ | 入库与 CI 证据的前提 |
| 2 | 每个文件的来源、版本 / 出图日期、格式版本？ | 可追溯 |
| 3 | 每个空间文件的坐标系？项目希望统一到哪个投影米制坐标系？高程基准？ | 平台**拒绝**经纬度坐标系，只接受投影米制；高程基准错一次全错 |
| 4 | DEM 的 NoData 值是多少？范围内出现 NoData 或无效几何时希望怎么处理（报错停止 / 标记复核）？ | 平台默认报错停止，不会静默填补 |
| 5 | 建筑、检查井、雨水口的编号是否稳定？以后更新数据时编号会不会变？ | 映射关系依赖编号 |
| 6 | DEM 是裸地表（DEM）、含建筑与植被的表面（DSM），还是混合？ | 决定建筑如何处理 |
| 7 | 建筑是否完全阻水？有无地下车库出入口 / 底层架空等开口？屋面雨水去向：接管网、散排到地面，还是未知？ | 决定屋面 → 管网耦合 |
| 8 | 地表类型与糙率 / 土壤的对应关系有无本地规范或经验值？ | 有则采用并注明出处，无则由项目方提出待您确认 |
| 9 | 有无本地建筑密度 / 街区孔隙率之类的参数来源？ | 无则由项目方按规则表推导并注明 |
| 10 | 地面雨水口 → 检查井、屋面 → 检查井的对应关系是否已有资料？ | 平台只接受**显式**对应表或人工确认，不接受"就近"自动匹配作为最终结果 |
| 11 | （含河道时）河道边界编号、进 / 出流方向、边界类型（水位 / 流量）？ | 河网耦合契约 |
| 12 | 您认为合格的结果长什么样？例如：网格单元数量级、哪些井必须被耦合、历史积水点位置、某场暴雨的观测水深。 | 作为验收参考；没有也请说明 |

## 5. 交付方式与我们收到后会做什么

1. **打包**：一个压缩包，内部按本目录结构放置（`boundary/`、`terrain/`、`buildings/`、`landcover/`、`swmm/`、可选 `dflowfm/`、`soil/`），加上第 4 节说明页。文件名可以保持原样，不必改成模板里的名字。
2. **自检**：项目方运行 `scau_preproc.package_selfcheck` 做预检（边界是否闭合、DEM 是否覆盖范围、对照表里的井是否存在于 `.inp`、地表编码是否都有规则等），把红 / 黄 / 绿结果反馈给您。**红项需要您补数据或补说明，项目方不会代填。**
3. **确认**：项目方把第 3 节中由项目方提出的映射规则（第 8、9、10 项）整理成表回给您确认。
4. **入库**：双方确认后，按 `acceptance_checklist.md` 逐项验收，通过后作为固定回归样例进入项目测试，此时 M287-D / D-5 状态由 BLOCKED 转为进行中。

联系项目方之前有任何格式问题，直接把原始文件的**一小部分**（任一图层几十个要素、DEM 一角）先发过来试读，比先整理后返工省时间。
