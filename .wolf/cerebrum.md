## Key Learnings

- **Project:** SCAU-UFM
- The `windows-msvc` preset in `CMakePresets.json` expands `CMAKE_TOOLCHAIN_FILE` from `VCPKG_ROOT`; when that env var is missing, CMake resolves the path to `/scripts/buildsystems/vcpkg.cmake` and configure fails immediately.
- **Description:** SCAU urban flood model. C++20 numerical core (Anisotropic DPM HLLC) with embedded SWMM and D-Flow FM 1D engines, fully coupled by `CouplingLib`.
- SWMM 5.2 API: `swmm_setValue(swmm_NODE_LATFLOW)` writes the API inflow buffer; `swmm_getValue(swmm_NODE_LATFLOW)` reads the *routed* value, so read-back is only meaningful after a routing step. `swmm_setValue(swmm_NODE_HEAD)` sets outfall stage (enables river->pipe backwater coupling). End-of-simulation is signalled by `swmm_step` resetting elapsed time to 0.
- SWMM solver keeps process-wide global state: at most one open project per process (`SwmmEngine` uses an atomic singleton guard).
- D-Flow FM BMI 1.0: `get_var` returns an engine-owned pointer valid only until the next BMI call; single-point writes use `set_var_slice`; resolve symbols with `decltype` against the vendored `bmi.h` so the ABI cannot drift silently.
- CouplingLib core mutation model: `apply_*` only enqueue `CouplingEvent`s; cell volume/h change only on `replay_pending()`. Mirror this for any new exchange path.
- MockDFlowFMEngine whitelists variables: `water_level`, `discharge`, `lateral_discharge`, `gate_opening` (project-standard names; the real BMI kernel may use `s1` etc. — keep variable names configurable at the driver/config level).

- [2026-07-28] BOUNDARY GHOST SIDEDNESS: in run_flux_core, a boundary edge stores its normal left->right; when the inside cell is the RIGHT cell, the ghost/outside state is the Riemann LEFT state. Passing (inside, outside) unconditionally inverts flow direction for ASYMMETRIC ghosts (WaterLevel) while symmetric Open copies mask the bug completely. Any new boundary kind with an asymmetric ghost must order Riemann args by adjacency (inside_is_left) and sign residuals accordingly.
- [2026-06-26] MSVC warnings-as-errors treats discarded `[[nodiscard]]` return values inside `EXPECT_THROW` as C4834. Wrap such calls with `static_cast<void>(...)` in tests.
- [2026-07-16] Windows MAX_PATH bit the deep worktree path: MSB3491 (cannot write .tlog, >260 chars) made 3 long-named fault-controller ordering tests silently "Not Run" under `.worktrees/<name>/build/windows-msvc`. Fix: configure a SHORT build dir (e.g. `cmake -S <worktree> -B H:/scau-b -DCMAKE_TOOLCHAIN_FILE=H:/githubcode/vcpkg/scripts/buildsystems/vcpkg.cmake`); 112/112 pass there. Check for MSB3491 whenever tests show Not Run in a worktree build.
- [2026-07-16] bug-020 (caught by M240-ROOF golden): the SWMM API lateral-inflow buffer PERSISTS until overwritten — any per-substep write scheme must zero last substep's written nodes at substep start (adapter begin_step now does), or nodes not re-written keep routing stale flow. Single-substep unit tests cannot see this class of error; multi-substep goldens can.

- [2026-06-12] Vendored C sources failed to configure: root project() only enables CXX. Any cmake/third_party module adding C code must call `enable_language(C)`.
- [2026-06-12] Non-ASCII characters (em-dash, section sign) in C/C++ comments break MSVC under codepage 936 (C4819 + warnings-as-errors). Keep code comments ASCII-only.
- [2026-06-12] `EXPECT_DOUBLE_EQ` on recomposed floating-point aggregates (e.g. system mass from h*phi_t*area) is flaky; use `EXPECT_NEAR` with ~1e-9.
- [2026-06-13] Friction tests must compare against a frictionless control run, not the initial momentum: closed-box HLLC momentum exchange can legitimately increase per-cell hu.
- [2026-06-13] After killing a ctest run, ALWAYS kill leftover test_* processes and grep build output for LNK1168 before trusting test results — MSBuild link failures leave stale exes and ctest runs them silently (false hangs/false passes). Verify with `grep -c LNK1168 == 0`.
- [2026-06-13] `grep -oE "H:[^ ]*"` on MSVC output eats backslashes from Windows paths; piping into `rm` silently no-ops (rm -f on nonexistent path exits 0). Delete by basename with `find -name X -exec rm` instead.
- [2026-06-13] bug-014: when adding validation to a shared validator (validate_dpm_fields_match_mesh), validate ONLY the field your task introduces. Adding phi_t in (0,1] broke existing fixtures using phi_t=1.25 to drive pressure-pairing math. Pre-existing scalars had no range checks; do not retrofit constraints as scope creep — enforce domain at the specific call sites that need it (source terms already do).
- [2026-08-01] Git Bash (MSYS) mangles MSBuild switches passed through `cmake --build ... -- /m` into POSIX paths (MSB1008 "只能指定一个项目"). Use `cmake --build <dir> --config Debug --parallel` instead of passing /m through.
- [2026-08-02] MSVC-only local verification misses GCC -Wextra diagnostics: C++20 designated initializers that omit fields (even ones with default member initializers) fail Linux CI via -Werror=missing-field-initializers. In tests/new code, prefer value-init + member assignment, or initialize every field; treat MSVC-green as insufficient before pushing C++ touching CI with SCAU_WARNINGS_AS_ERRORS=ON.
- [2026-08-04] Any run/golden over the mixed-minimal STCF profile that asserts whole-domain phi_t*h*A closure under COUPLED transients must set enable_cvc_spatial_phi_t_correction=true: the profile's internal edge carries a phi_t 1.0/0.8 jump and the default-off HLLC path leaks ~4% storage over 10 epochs (M253 limitation; G23 opt-in fix closes it to machine epsilon). Lake-at-rest-only tests are unaffected.
- [2026-08-04] Windows DLL name collision for any executable that both links vcpkg netcdf (STCF I/O) and loads the real dflowfm.dll: the loader binds netcdff.dll's netcdf import to the already-loaded app-local vcpkg netcdf.dll (missing nc_*_chunking_ints) -> LoadLibrary error 127. Applies to scau_sim real mode too - real-mode deployment must ship the runtime's netcdf.dll beside the exe.
- [2026-08-06] Whole-system PHYSICAL storage must sum phi_t*h*A over all h>=0 water; the symbols-reference h>=h_wet M_ref is a separate tolerance/diagnostic scope. Reusing h_wet in physical storage creates a discontinuity when cells cross near-dry (bug-190).
